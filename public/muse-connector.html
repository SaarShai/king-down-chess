Muse tool documentation

Use the King Down tools in Meta Muse to start, play and end casual games against the computer. This page comes from the tool listing that each MCP client gets.

The listing is the answer to tools/list that each MCP client gets, and so the portal's MCP snapshot.

Connection and authorization

Endpoint: https://kingdown.dev/muse/mcp. Transport: stateless MCP over Streamable HTTP. Send JSON-RPC requests with POST. OPTIONS gives the CORS preflight response. GET streams and JSON-RPC batches are not supported.

Authorization: OAuth 2.1 with the authorization code flow and PKCE S256. Muse uses a pre-registered public client, with no client secret. The scope is openid. Send the access token in Authorization: Bearer <access_token>.

Authorization server: https://utqzovjmclfyojedmwok.supabase.co/auth/v1.

Protected resource metadata: https://kingdown.dev/.well-known/oauth-protected-resource/muse/mcp. The resource and token audience are https://kingdown.dev/muse/mcp.

The class comes from the read-only hint: a read-only tool is a Read, and each other tool is a Write. No tool is a Sensitive write: no tool sends a message, spends money, or shares data outside King Down. Each tool acts only on the games of the signed-in King Down account. The account comes from the access token, never from a tool field.

Results

Each result starts with one or two sentences that Muse can speak as they are. Detail lines follow: the board, the choices or a link. structuredContent gives the same facts and agrees with the output schema of the tool. No result has a widget or an image.

Status and retries

kingdown_move and kingdown_end give a result value:

resultMeaning
playedYour turn played, and the computer replied in the same call.
computerAn earlier call stopped before the computer moved. The computer moved now; say your move again.
choicesThe words fit more than one move. The result gives numbered choices with their move_ids. Nothing played.
refusedThe words fit no legal move. The result gives the reason and some legal moves. Nothing played.
pendingThe turn has more actions (a king power such as Haste). The result gives the next choices. Nothing played.
changedexpected_revision is not the revision of the game. Nothing changed; the result gives the current state.
endedThe game ended.
  • kingdown_move and kingdown_end carry expected_revision, the revision of the last result for the game. When it is not the revision of the game, the tool changes nothing and gives the current state (changed).
  • A write that comes again changes nothing more. The same kingdown_move or kingdown_end again has an old expected_revision, so it gives changed, with the current state and the last turns. The same request_id again gives the same game in its current position, with computer: []: the first move of the computer does not come again. Thus each tool has the idempotent hint.
  • The server makes the command ID of each write from the game ID, the revision and the actions; kingdown_new_game makes it from request_id. Two equal calls at the same time have the same command ID, and the game service plays the command once: the second call gets the receipt of the first, or STALE_REVISION.
  • After a lost reply, send the same call again: the answer gives the current state. Or read the game with kingdown_view.

Errors

A call that a tool refuses sets isError. Its text is one fixed sentence, and its structuredContent is { "code": "<code>" }. The text never repeats the input. The text of the game service never goes to Muse; this table gives the sentence for each code of the game service.

The connector has more codes, each with its own fixed sentence: NO_GAME (no game against the computer), PERSON_GAME (the game is against a person; the sentence gives its link), NOT_STARTED (the setup of the game is not complete) and INTERNAL_ERROR (any other fault; "Could not update the game. Try again."). The server log records the tool name and a fixed error category only.

A call that does not fit the input schema stops in the MCP SDK, before the tool runs. Its result sets isError and has no structuredContent. Its text starts with "Input validation error:" and names the field and the rule that the input breaks.

Rate limits

The server counts each counted call for the account before the game work starts, so a call that the game then refuses also counts. Two refusals come before the count and count nothing: a call that does not fit the input schema, and a kingdown_move call with no said and no move_ids. The website uses the same counters for the same actions. The reads have no count limit. The limits of the HTTP edge (above) apply to all calls.

CounterToolsLimit for each account
kingdown_createkingdown_new_game60 calls in 60 seconds
kingdown_computerkingdown_move120 calls in 60 seconds

A call over the limit gives code RATE_LIMITED and "Too many requests. Wait one minute, then try again."

kingdown_games: Your games

Class: Read. Limit for each account: none.

Lists your unfinished King Down games, your turn first. Each game has its ID, whether it is against the computer or a person, whether it is your turn, the move number, your colour, the computer level and a link to the game on the website. It gives no opponent name.

Side effects: None. It reads the unfinished games of the account.

kingdown_new_game: New game

Class: Write. Limit for each account: 60 calls in 60 seconds.

Starts a new King Down game against the computer, with fairy pieces unless classic is true. A new request_id makes a new game; the same request_id on a retry returns the same game. The result gives your colour, the back rank, the computer's first move when it plays White, and the board.

Side effects: It makes one casual game against the computer in the account; the game also shows on kingdown.dev. When you play Black, the computer plays its first move. The same request_id gives the same game again, not a second game.

kingdown_move: Play a move

Class: Write. Limit for each account: 120 calls in 60 seconds.

Plays your move in a King Down game against the computer, from words (said) or from exact move IDs of earlier choices (move_ids), or both: the IDs first, then the words. Words that fit several moves give numbered choices and play nothing; words that fit none give the reason and some legal moves. A turn with more actions (a power or a card) gives the next choices and plays nothing until it is complete. A complete turn plays, and the computer replies in the same call. When expected_revision is not the game's revision, nothing is played and the current state comes back.

Side effects: It plays your complete turn and the computer's reply in that game; casual games change no rating. Choices, a refusal, an unfinished turn and an old revision play nothing.

kingdown_end: End a game

Class: Write. Limit for each account: none.

Ends a King Down game against the computer: resign (the computer wins) or abort (no result; only before each side has played a turn). When expected_revision is not the game's revision, nothing changes and the current state comes back.

Disconnect and delete data

On kingdown.dev, open Settings → Account → Disconnect Muse. This ends the link and deletes the games that you started in Muse at once. Games that you started on the website stay in your account, also when you moved in them through Muse.

Muse does not tell King Down when you disconnect inside Muse. A daily check also deletes the games that you started in Muse when the link has no session, or has no use for 30 days. This applies also when you are still connected. Account deletion also deletes the games that you started in Muse.

For account deletion and other data requests, see Delete your data and the Privacy policy. For help, write to hello@kingdown.dev.
