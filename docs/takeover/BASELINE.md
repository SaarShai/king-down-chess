## Q6 chain: completed, preserved, UNVALIDATED

The chain ran after the review document and the review's warning applies: a done marker is not proof
of success. The plan's §3 acceptance was **not** applied.

| Stage | What happened | Defect |
|---|---|---|
| Generate (`nnue-g1`) | 79,314 new games appended to an existing 686-game prefix; 80,000 lines total. | Exited 1. `writeSummary` read the 725 MB file as a string (`ERR_STRING_TOO_LONG`), so the summary still says 686 games. The run header printed `rules {}` and the records carry **no rule/pool/source stamp** anywhere (checked first 10 MB and sampled lines). The writer loaded at 04:50 predates the stamping code (05:05 resume-protection agent). |
| Sample | 7,487,107 positions, 752,039 held out. | Replayed under **today's** defaults; no source-stamp validation, no input fingerprint in `positions.json`. |
| Train | Residual net, 16 epochs, best val at epoch 14, 45,153 weights → `src/ai/nnue/weights.ts` (08:56). | Candidate was written into the shipped source path, not kept separate. |
| Match d3 | 1,600 games, `nnue-res-d3`: +99 ± 14 Elo, LOS 100%. | The 400-game rejection gate was skipped. The arm pins the linear params in `eval-residual.json` but **not the net blob**: the net came from the ambient `weights.ts`. |
| Match d4 | 200 games, `nnue-res-d4`: +108 ± 37 Elo. | Confirmation size not per plan; same pinning gap. |
| Bench | Linear 388k nodes/s, residual 282k nodes/s; 1 s search depth 6.08 vs 5.92. | Speed is inside the browser's one-second target (depth does not drop below 5). |

The prefix: `nnue-g1.summary.json` describes the old run (`seed 202`, `sample 700`, 686 games). The
appended cohort came from `queue3.sh` (`seed 914`, `sample 4000`, explicit `--rule` flags that equal
today's defaults except paladin semantics, which the launch omitted). Move replay must classify what
those 79,314 games actually played before any of them enter a training corpus.

**Ownership:** the Q6 outputs stay in place and are read-only until Phase 3 accepts or rejects them.

## Rules for the rest of the takeover

1. Long simulations run in a Git worktree pinned to a committed revision, never in the working
   tree under edit (LESSONS.md 2026-09-14: a live chain started during a half-edit played a broken
   engine).
2. One CPU-heavy job at a time, scheduled explicitly; no campaign starts without its own accepted
   dataset and pinned inputs.
3. A `done` marker is written only after the stage's validation step passes.
