## Confirmed dependency and caller boundary

- `src/match/worker.ts` directly imports `ai/search` and `ai/skill` for `chooseMove`. Removing only those imports is insufficient: `Game → GameRules` also retains search/evaluation through `positionKey`, `search` and `searchLegal`.
- `GameRules.positionKey` is enforcement state: `Game.key()` uses it for repetition. The fixed Zobrist tables and full position hash belong with rules. Search's `initPosition` also relies on `positionKey` filling its private two-word scratch buffer; preserve both values and this behavior.
- `GameRules.search` has one product caller, the inline fallback in `Engine.think` in `src/game.ts`. Its owned rules/design scope can move to the existing `searchOwned` entry with mandatory explicit rules. `GameRules.searchLegal` has no product caller; its isolation-test caller must move to an explicit owned search probe rather than retaining an evaluator import in `GameRules`.
- `LocalMatch.chooseMove(options): Promise<string>` has one product caller, `src/match/service.ts`; fixture/smoke callers also use it. Keep that interface, service transaction/receipt behavior, HTTP/MCP contracts and model-visible data unchanged.

## Smallest implementation

1. Move the stable tables from `src/ai/zobrist.ts` and full position hashing into `src/rules/position-key.ts`. `GameRules` calls the rules-owned hash. Search imports the same tables/hash and retains its scratch-buffer behavior. Remove the old module rather than adding a compatibility wrapper. 2. In `src/ai/search.ts`, make `searchOwned` take explicit owned rules and perform the existing rules/design enter/restore and entropy-callback rejection. Update `Engine.think` to pass `context.rules`; remove `GameRules.search` and the unused product `searchLegal` method. Do not widen `GameRules` or expose ambient search to product callers. Keep the import-boundary test aligned with the explicit owned entry, without file-specific exemptions.
3. Lift the existing Node `chooseMove` calculation into one Node-only `src/match/search-worker.ts`, built beside the runtime by `tools/plugin-runtime-build.mjs`. Use a lazy search worker owned and closed by each `LocalMatch`; do not share its mutable evaluator/search globals across matches. This helper uses the existing Node linear evaluator, not the browser worker's residual evaluator.
4. Keep the private operation name `chooseMove`. The new enforcement worker validates options and returns a tagged, cloned search context containing its engine/revision, effective rules, position, prior repetition keys, ply and ordered legal moves. `LocalMatch` accepts either the existing archived worker's LAN string or this explicit new reply. Only the new reply invokes the helper; no guessed version or error-based fallback. The helper lifts the current level caps, opening window, reset, search and blunder/random ordering unchanged. Validate its result against the captured stored-engine legal moves and reject an obsolete revision before returning. The stored worker remains the authority when the service applies the LAN with its expected revision.
5. Keep this context private to Node worker transport. It is not a save field, account DTO, HTTP response or model projection. Preserve bounded failure/timeout behavior and terminate the helper on match close/failure; late replies cannot answer a replacement request.
6. Remove evaluator-only source files from the development fingerprint inputs only after this dependency cut. Mechanical hashing now lives under the already-hashed rules tree. Compiled identity continues to hash all emitted enforcement-worker bytes through the unchanged `buildWorker` algorithm; never suppress bytes or relabel a save to obtain equality.

Product/build scope is `src/rules/position-key.ts`, removal of `src/ai/zobrist.ts`, `src/ai/search.ts`, `src/game-rules.ts`, `src/game.ts`, `src/match/{worker,index,search-worker}.ts` and `tools/plugin-runtime-build.mjs`. `src/match/service.ts`, public protocols, rules, evaluator weights, skill settings and browser AI behavior need no product changes.
