# Compatibility inventory

Status: current at commit `73387e66`. Parent: U09 ("Compatibility code has a supported-data reason and removal policy"). Ticket: [staging-first-game 58](../staging-first-game/issues/58-compatibility-inventory.md).

This file lists each piece of code that accepts old stored data, old links, old clients or an old deployment. For each item it gives the supported data, where that data lives, how to measure it, the removal trigger and the owner decision. Each citation is `file:line` at `73387e66` plus a symbol name. Other work changes some of these files, so find the symbol first if the line moves.

"P" below means the date of the first production publish of a build that contains the item's replacement. At `73387e66`, production does not contain this build. Production SQL counts need an operator with read access. Never print a key or a connection string to run them.

## Notes

- **`shortcut:` comments.** `src/` has one: `src/match/service.ts:429` (C1). `tools/plugin-protocol-fixture.ts:116` is a test fixture note about read isolation, not compatibility. The older `ponytail:` comments (`src/online/safety.ts:108`, `src/online/deadline.ts:54`, `src/rules/rules.ts:853`, `src/rules/engine.ts:1860`, `src/account/profile.ts:55`, `src/online/jobs.ts:40`, `src/match/service.ts:484`, `src/ai/search.ts:299,309`, `src/plugin/server.ts:110`) name no compatibility fallback.
- **Checked, not compatibility.** `?rules=2017|2021` (`src/main.ts:43-44`) is a product feature that plays an older rule set. The `MATCH_INCOMPATIBLE` refusals (`src/match/service.ts:101,193,205,212,237,242,390`) fail closed and keep no old path. The cache clear at `src/online/cache-policy.ts:141` is upgrade recovery. `tools/vercel-check.mjs:188` proves that old paths (`/play.html`, `/j/`) are closed. The other "fallback" hits (clipboard, AI worker, CSS) are browser fallbacks, not old data.
- **Order.** C3, C4 and C5 depend on C2. Do C1, C2 and C14 first after P. Then C3 to C5 when their counts reach 0. C15 depends on the connector move.
- **Release rule.** A new compatibility path names its supported data, its measure and its removal trigger in this file in the same change.
