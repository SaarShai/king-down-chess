# Web adaptation: test and device gate

**Choose option 1.** Use the website HTTP boundary with real services and a disposable PostgreSQL database as the main seam. Keep the pure tests. Add one top-level browser driver, registered as `web-online`. Reuse the plugin assertions and keep the plugin checks. Reject option 2. A second copy of each plugin check adds upkeep but does not prove browser routes, website sign-in or worker safety. Screenshots alone also fail the gate. (E1, E2, E5)

Decided by delegation in [the test gate ticket](issues/16-test-gate.md), after three independent reviews. No check ran for this document. The decision gives no run, merge or publish go. The spec's Testing Decisions take this gate at the spec approval ([ticket 18](issues/18-approve-spec.md)). (E12)

The WebKit job and a new Firefox job that run `web-online` get a PostgreSQL service, `npm run plugin:db:init-test` and their Playwright browser install (`npx playwright install firefox` for the Firefox job). `web-online` uses no CDP. `launch()` in `tools/lib/checks.mjs` gets a Firefox branch, and `STEP` gets a CI factor for Firefox. The wrapper still runs type checking and drawing tests. A full `npm test` also collects browser test files; it is not a unit-only command. Keep that full run in CI or on the M1. Run only one named browser check at a time on this Mac. Keep full browser sweeps, render comparisons and load measurements on the M1 or CI. The runner's three available slots do not change this task's stricter Mac limit. (E4, E5, E7; task house limit)

Use CI for the required database checks. An M1 run can replace that evidence only if it has its own disposable database and all required database cases execute. Use the M1 for long browser and render work. Kaggle is the recorded tournament route; this adaptation needs no tournament. Do not send the web test gate there. A run needs the owner's go only where AGENTS.md and docs/QUEUE.md say so; CI test runs need none. (E6, E7)
